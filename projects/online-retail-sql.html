Online Retail SQL Audit & Event-Driven Pipeline

A SQL-only project. No dashboard, no semantic model, no Power BI — just business rules, triggers and an audit log designed so the data quality issues stopped surfacing first through customer complaints.

The problem

Order and fulfilment records weren't being checked until something obviously went wrong. Status mismatches, financial inconsistencies and fulfilment gaps could sit in the data for a while before anyone noticed — and when they were noticed, it was usually too late.

What I built

SQL business rules covering status transitions, financial reconciliation and fulfilment integrity. Triggers and an audit log that record both the change and the rule outcome, so exceptions accumulate in a structured table rather than as scattered ad-hoc alerts.

Validation

The whole project is the validation layer. The shift is from manual periodic review to event-driven exception monitoring — the same checks run consistently whenever a record changes, instead of being reapplied by hand when someone has time.

What changed

An exception-oriented data quality layer that surfaces issues early and makes operational checks repeatable. Less of the "why didn't we catch this?" conversation; more of the kind that starts from a list of known exceptions.
