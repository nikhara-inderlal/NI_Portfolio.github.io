Problem
Finance and Assurance reporting was fragmented, with inconsistent KPI logic and weak audit paths from source data to published figures.
Build
Built and supported a governed Fabric reporting layer with Direct Lake semantic modelling, T-SQL and Spark curation, reusable measures, snapshot logic and exception reporting.

Created a stronger reporting foundation for finance stakeholders: consistent metrics, point-in-time workforce reporting, reconciliation checks and visible mapping exceptions.

Business problem

Finance and Assurance teams needed a single governed reporting layer that could support KPI and variance reporting, point-in-time workforce snapshots and exception monitoring. The prior setup made it difficult to reconcile numbers or see where missing reference mappings affected downstream reporting.

My role and ownership

Contributed across the curation, semantic model and report layers: T-SQL and Spark notebook preparation in Fabric, reusable base measures, Power BI and Excel outputs, UAT support, controlled DEV-TEST deployment and stakeholder updates through Azure DevOps and Confluence.

What I built

Created and enriched reporting tables, extended dimensional structures for historical workforce snapshots, supported Direct Lake semantic modelling and helped deliver reusable measures so the same KPI meant the same thing across outputs.

Validation and reliability

Validated outputs across source extracts, curated datasets and final reports using reconciliation and tie-outs. Built exception reporting for missing reference mappings such as payment attributes and staff identifiers so data gaps surfaced before they distorted downstream reporting.

Outcome

Finance and Assurance stakeholders now consume more consistent governed metrics with a clearer path from source to published figure. The strongest hiring signal is not only the dashboard layer, but the modelling, reconciliation and delivery discipline behind it.
