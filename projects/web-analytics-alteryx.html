Multi-site GA4 to BigQuery Pipeline

Multiple websites, one analysis layer. This was the project where I leaned hardest into analytics engineering — schema design, controlled access, audit logging — rather than dashboard work.

SectorSales & marketing analytics
My roleAnalytics Engineer
PeriodAug – Sep 2025
StackBigQuery, GA4, Alteryx, SQL Server, Power BI, DDL
Multi-site GA4 consolidation
BigQuery schema design
Service-account integration
Audit logging & variance views

The problem

GA4 exports come out nested and inconsistent across sites. Sales and marketing needed one analysis-ready surface to compare websites month over month, instead of repeating per-site reconciliation by hand from the Google Analytics UI.

What I built

GA4 export wired into BigQuery on a scheduled daily load. Combined DDL schema design across the sites, with parameter unnesting that turns nested event properties into queryable columns. Alteryx connected through a service-account JSON key and ODBC; from there, curated outputs feed Power BI MoM/YoY variance reporting.

Validation

SQL Server audit logging on every run, so refresh freshness and key integrity are visible rather than silent. Missing partitions, late-arriving rows and referential gaps show up explicitly — the dashboards above stop being a guess about whether the data made it through.

What changed

A scheduled, consolidated multi-site web analytics layer that the team can actually trust as the starting point for analysis. Less time spent wondering whether the numbers are current, more time spent on the questions behind them.
