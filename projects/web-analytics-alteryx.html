Web Analytics API Pipeline

Alteryx + Google Analytics API workflow producing dimensional and flattened reporting layers.

SectorDigital / Web Analytics
RoleAnalytics Engineer
EngagementProject engagement
ToolsAlteryx, Alteryx Server, Google Analytics API, SQL Server

Context

Marketing wanted self-serve reporting on website behaviour, channel performance and campaign conversion without continually exporting from the Google Analytics UI. The data needed to land in SQL Server in a shape downstream BI tools could use.

Approach

Built an Alteryx workflow that called the Google Analytics API on a schedule, handled paging and quota limits, and landed both a dimensional layer (for star-schema downstream use) and a flattened reporting layer (for ad-hoc analysis). Scheduled via Alteryx Server.

Modelling & preparation

Dimensional layer: dim_date, dim_channel, dim_campaign, dim_page, fact_session, fact_event. Flattened layer: one denormalised wide table for analysts who don't want to write joins. Both layers refresh from the same source workflow so they stay consistent.

Validation

Cross-checked Alteryx outputs against the GA UI for matched date ranges, monitored row counts and API quota usage over the first month, and added explicit run-status logging so failures surface to the analytics team instead of going silent.

Outcomes

Marketing now has reliable channel and campaign analysis without manual exports. Downstream dashboards refresh on a schedule, and the dual-layer design means both star-schema users and ad-hoc analysts get what they need from the same source.
