Multi-site GA4 to BigQuery Analytics Pipeline

GA4 export to BigQuery with scheduled daily loads, DDL schema design and parameter unnesting across multiple websites, with Alteryx-driven curation, SQL Server audit logging and MoM/YoY variance reporting.

SectorInternal Sales & Marketing analytics
RoleAnalytics Engineer
EngagementAug – Sep 2025 (enhanced in subsequent phase)
ToolsBigQuery, GA4, Alteryx Server, SQL Server, Power BI

Context

Sales and marketing needed consolidated web analytics across multiple websites without relying on the Google Analytics UI or manual exports. The team wanted analysis-ready tables in a single, governed warehouse, with consistent schemas across sites and a refresh cadence the business could trust for daily and month-on-month reporting.

Business problem

GA4’s native export schema is highly nested (event_params, user_properties, items) and varies per site, so meaningful cross-site analysis needed flattened, conformed tables rather than raw exports. There was no consolidated multi-site analytics layer, no audit trail on refresh health, and no governed variance reporting.

Approach

Implemented the GA4 export to BigQuery with scheduled daily loads and combined schema design (DDL) across multiple websites, with parameter unnesting so analysis-ready tables exposed event-level fields as columns instead of nested arrays. Alteryx was then used to extract curated BigQuery data into fact and dimension structures for downstream reporting, with SQL Server audit logging to validate data freshness and key integrity each run.

Modelling & preparation

Designed the combined BigQuery schema with DDL so all sites landed in a consistent shape. Used parameter unnesting to surface GA4’s nested event parameters as queryable columns for analysis-ready tables. Consolidated tables across multiple websites for cross-site reporting. Curated data was then shaped into fact and dimension structures in the downstream layer for Power BI consumption.

Service accounts & integration

Configured service accounts for controlled BigQuery access, and connected Alteryx to BigQuery via a JSON key and ODBC for the curated extracts. This kept credentials managed centrally and avoided per-user authentication for scheduled workflows.

Audit logging & reliability

Implemented SQL Server audit logging to validate data freshness and key integrity on every run, so missing partitions, late-arriving rows or referential gaps surfaced explicitly rather than failing silently downstream.

Reporting

Enhanced downstream reporting with MoM/YoY variance views across key segments in Power BI, so sales and marketing could see month-on-month and year-on-year shifts in traffic, channel mix and conversion behaviour at a glance rather than reconstructing comparisons in spreadsheets.

Outcomes

Sales and marketing now consume a consolidated, scheduled, multi-site GA4 dataset with explicit freshness and integrity checks, plus MoM/YoY variance views for fast trend interpretation. The combined schema means cross-site analysis works without per-site reconciliation, and the audit log means refresh problems are visible rather than hidden.

Reflection

The biggest lift came from treating GA4’s nested schema as a modelling problem rather than a query-time inconvenience. DDL-defined combined schemas with parameter unnesting once, upstream, made everything downstream — Alteryx curation, audit logging, variance views — cleaner and more durable.
