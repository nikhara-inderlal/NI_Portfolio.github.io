Dashboard Week: Rapid Analytics Delivery Series

One week of daily challenges: quick scoping, messy data prep, API exploration, dashboard design and reflection.

SectorLearning / Rapid Delivery
RoleAnalyst (rapid delivery)
EngagementOne week
ToolsTableau, Power BI, Alteryx, BigQuery

Context

Dashboard Week is a Data School training tradition: one analytics challenge per day for a full week, with a same-day delivery and a written reflection. The point is to practise scoping, simplification and judgement under time pressure.

Business problem

Each day's challenge had a new dataset, a new tool combination and a one-day deadline. The practical problem was deciding what 'useful' looks like in the time available, not what an ideal solution would look like with infinite time.

Approach

Each day: read the brief, quickly assess the dataset and decide what a useful output would look like in the time available, lean on Alteryx / Tableau Prep / Regex for messy prep, deliver a focused dashboard, and write a same-day reflection on what worked and what to do differently next time.

Modelling & preparation

Different stack each day depending on the dataset: BigQuery + Power BI for one challenge, Tableau Prep + Tableau for others, Alteryx for the web-scraping and API days. The common thread was small, clean, defensible models over speculative complexity.

Validation

Sense-checking each output against the source data before publishing, prioritising clarity over feature count, and using the reflections as a feedback loop into the next day's challenge.

Stakeholder delivery & handover

Each day ended with a same-day dashboard presentation and a written blog reflection; the delivery format itself was part of the practice, not just a side artefact.

Outcomes

Five completed challenges, five written reflections, and a sharper instinct for when to simplify, when to pivot off a plan, and how to prioritise a useful outcome over an overly complex technical path under deadline.

Reflection

The biggest single lesson was Thursday: knowing when to abandon an inefficient approach is more valuable than persisting with it. Across the week, the habit that mattered most was deciding what 'good enough' looked like before starting the build.
